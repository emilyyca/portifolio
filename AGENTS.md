# Regras obrigatórias — Portfólio Emily

- Primeiro leia integralmente `referencias.md`, `identidade.md` e `funcionalidades.md` antes de modificar qualquer código.
- Use **somente HTML5 semântico, CSS3 e JavaScript puro**. Sem React, Vite, Tailwind ou frameworks. Sem dependências desnecessárias.
- Crie `index.html`, `style.css` e `script.js`. Mantenha imagens dentro de `assets/`.
- Preserve a fotografia real `assets/foto-emily.jpg`. **Não a gere, retoque, troque, espelhe nem altere o rosto**. Use a fotografia apenas no bloco Sobre mim, com `<img>` e `object-fit: cover` caso precise encaixar. Ajuste o enquadramento com CSS (preferir `object-position: center 35%` como ponto de partida), conferindo visualmente para não cortar o rosto.
- Direção de arte: **minimalismo editorial contemporâneo**, com assimetria controlada, hierarquia tipográfica, respiro, grid elegante, linhas finas e fotos grandes. Não use design padrão de IA: sem cards iguais, gradientes, sombras pesadas, avatar circular, ícones gratuitos espalhados ou hero centralizado.
- As referências são inspirações, **não copie páginas, marcas, textos ou imagens de terceiros**.
- Faça a implementação **uma etapa por prompt**; não antecipe seções futuras. Nunca apague o que já estiver funcionando sem explicar.
- Use os dados reais em `identidade.md`. Não invente formação, experiência, projetos, GitHub, links do TCC nem screenshots.
- Site acessível: hierarquia de títulos, `alt` na foto, links identificáveis, foco visível, bom contraste, navegação por teclado, `prefers-reduced-motion`.
- Layout responsivo de 360px a desktop; sem rolagem horizontal ou imagem cortada inadequadamente.
- Respeite privacidade: não inclua telefone, endereço residencial, data de nascimento ou outros dados pessoais não definidos para divulgação.
- Ao terminar cada etapa: resuma em 2–3 linhas o que mudou, os arquivos alterados e como testar. Não afirme que testou algo que não foi testado.
